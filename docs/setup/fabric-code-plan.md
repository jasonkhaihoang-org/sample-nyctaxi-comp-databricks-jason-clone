> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the dlt, dbt and orchestration code run on the Fabric Lakehouse Domain with the DuckDB repo's models and business rules, in the plugin's `fabric_lakehouse` shape.

**Architecture:**
- dbt is retargeted in place: profile, macros, materialisation and DuckDB-to-Spark SQL. The August-era Fabric port at `27de00c` (`src/dbt/nyc_taxi_analytics.DataBuildToolJob/Code/dbt/`) is the reference for Spark translations of the models it shares.
- Each `ingestion/<name>_pipeline.py` becomes `ingestion/<name>_pipeline.Notebook/`, generated by the plugin, with the same source code under `ingestion/sources/`.
- `orchestration/` becomes the `nyc_taxi_refresh` Data Pipeline plus the `nyc_taxi_build_dbt` job notebook, both from the plugin's materializers.
- Live checks run from this host with the operator's `az login` against the Domain: plain dlt with Azure's default credential, and dbt over Livy with CLI authentication from a scratch profile. Nothing local is committed.

**Tech Stack:** dlt `filesystem` destination writing Delta, `vibedata-dlt-fabric-studio`, `dbt-fabricspark` 1.12, Spark SQL, Fabric Data Pipeline JSON, pytest.

**Spec:** Linear VD-6998; `docs/setup/requirements.md` R-02, R-03, R-04. Plugin: `_shared/platforms/fabric_lakehouse/{dbt,dlt,pipeline-notebook,orchestration,destination-staging,dialect}.md`, `_family/fabric/{orchestration-authoring,dbt-job-notebook}.md`. ## Review Focus

- A DuckDB function rewritten to a Spark one with different semantics. Covered by the live `dbt build` (data and unit tests) plus the January row-count parity with DuckDB in Task 5:
  - `date_diff` argument order and units
  - `date_trunc('week')` on Monday (ADR 0014)
  - integer division in `nullif` ratios (ADR 0016)
  - `strftime` patterns
  - `md5` over concatenated nulls in `trip_natural_key` (ADR 0007)
- Staging timestamp conversion: Spark `TIMESTAMP` is session-time-zone. The conversion must produce the source's wall-clock value, so `int_trips_conformed`'s `trip_key` set matches DuckDB's. Task 5 compares the key set.
- An activity, notebook or profile carries a non-portable id. Covered by `tests/test_platform_prose.py` (GUID guard) and the plugin's `validate-datapipeline.py`.
- `ops` re-reads the yellow trips for its generator. The months it reads must equal the months `tlc` loads, or shifts reference trips that aren't in bronze. Task 2 test: `ops_source` with `months=["2024-01"]` produces assignments only for January trips.
- A notebook cell order or magic that breaks the sandbox run (the plugin's `pipeline-notebook.md` § Editing). Covered by running each notebook's `notebook-content.py` as plain Python locally in Task 5.
