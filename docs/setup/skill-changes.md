# Skill changes

Repo maintenance. Build agents do not read this document.

This is what should change in the `vibedata-data-engineering` plugin, in Studio, or in the Domain CI bundles, as found while porting this repo to Databricks. Paths in the Reference column are relative to the plugin root unless another repo is named.

The rows inherited from the earlier ports are in the ledgers of the [Lakehouse repo](https://github.com/accelerate-data/sample-nyctaxi-comp-fabric/blob/main/docs/setup/skill-changes.md), the [Warehouse repo](https://github.com/accelerate-data/sample-nyctaxi-comp-fabric-warehouse/blob/main/docs/setup/skill-changes.md), the [Redshift repo](https://github.com/accelerate-data/sample-nyctaxi-comp-redshift/blob/main/docs/setup/skill-changes.md) and the [DuckDB repo](https://github.com/accelerate-data/sample-nyctaxi-comp/blob/main/docs/setup/skill-changes.md). Only the rows that also hold on Databricks are repeated here. The `.agents/skills/workarounds` rules point here when the gap they cover is specific to Databricks.

Evidence marked "probe" is [`../verify/2026-10-28-vd-7384-databricks-probe.md`](../verify/2026-10-28-vd-7384-databricks-probe.md); "runs" is [`../verify/2026-10-28-vd-7385-databricks-runs.md`](../verify/2026-10-28-vd-7385-databricks-runs.md); "seed" is [`../verify/2026-10-28-vd-7386-databricks-seed.md`](../verify/2026-10-28-vd-7386-databricks-seed.md).
